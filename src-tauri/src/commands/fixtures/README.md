# Backup compatibility fixtures

These fixtures contain synthetic English, Japanese and German records only.
They were generated by `python3 generate_historical_backups.py`; no application
or user database was opened. The script reads immutable Git revisions with
`git show`, extracts each producer's `db.rs` / `tags.rs` SQL table definitions
and migration column tuples, inserts controlled records, and selects precisely
the fields declared by that producer's `BackupData`. It does not execute old
Rust init code or replay old sync triggers. The stored `producer_commit` is
schema/format provenance, not a claim the old app produced these files.

| Version | Producer source | Distinct compatibility input |
| --- | --- | --- |
| 1–3 | No producer in available Git history; first commit exports v4 | Explicit synthetic minimum-required / dictionary / phrase shapes; missing optional tables and omitted per-row English defaults |
| 4 | eb772ddf9fa0b29ed460518288ddcfbc85865c22 | Original table columns; mixed languages; review schedules and logs |
| 5 | 1daad927beabf0815e7dc8719095af6b0860705f | Folder organization and older phrase schema |
| 6 | c2288b0bb78c8a33d95c1ba22b8ae4488b0bc5dd | Context meanings and phrase alternatives |
| 7 | 1307035e1c7b0f7ea78fef55e8d6ce85ca11f600 | Aliases and personal meaning metadata |
| 8 | fc47ce5a590ca5453c0c73dc7f2b5834cfa3ab7c (`v0.4.5`) | Tags, old file columns and no saved-context tables |
| 9 | 2e0c8ddd9f6ae4b15517e37bb8fa9b0f95ad1ee2 | Old saved snapshots without dictionary/media/document extensions; tombstone and undo receipt |
| 10 | Current Rust material importer | Valid YouTube subtitle/media identity and saved snapshots, with no downloaded audio |
| 11 | Current Rust document importer | PDF source and UTF-16 locations without v2 origin |
| 12 | Current Rust document importer | Clipboard/webpage v2 origin, source identity and saved snapshots |

Versions 4–9 are in `historical_backups.json`. Version 9 snapshots and undo
receipts use deterministic synthetic values following the producer's field and
identity rules. Versions 1–3 and 10–12 are built in the Rust compatibility tests,
so their different defaults/provenance are visible alongside the assertions.

`v0_4_5_schema.sql` contains the tag's business table DDL with its migrated
columns, without post-tag saved/material/media/document tables or sync state.
The upgrade test inserts mixed-language rows into this schema, upgrades through
current `init_db`, inspects the pre-migration safety copy, and performs two
portable export/restore hops. This validates a tag-derived schema fixture;
verification against a binary-generated database remains native QA work.

Round-trip comparison ignores only the local autoincrement `saved_records.id`,
which is not a portable identity. It compares record IDs, snapshots, original
sentences, personal notes, history, tombstones, receipts, and source identities.
JSON stored inside SQL text columns is compared by parsed value. The safety
copy tests separately compare local sync identities and queued changes; portable
exports intentionally do not contain the entire sync engine state.
