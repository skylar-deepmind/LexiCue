# LexiCue 局域网设备同步方案（首版评审稿）

2026-11-08 · 面向产品、开发和测试。核查基线：本地 main，HEAD `86d8666` 加当前工作区未提交的 iOS、阅读、标签和同步相关修改。以下“现状”来自源码；其余是拟议行为。尚未实现 LAN 同步，也没有本方案的双机实测数据。

**给用户的承诺：在「设置 → 设备同步」配对一次。以后两台设备在可互通的局域网内同时运行时，打开即同步，使用中自动同步。** 例如，外出时在 iPhone 收藏一句话，回家打开 iPhone 上的 LexiCue，运行中的 Mac 会收到这条收藏；Mac 当天补好的译文也会传回手机。即使原音频只在 Mac 上，手机也能读正文、字幕和已有译文。只有当对方已把更改写入资料库并回执，本端才会把这次交换显示为“已同步”。

首版限定 **一台 Mac + 一台 iPhone**。Mac 提供监听，iPhone 发起一条双向连接；两端各自拥有完整的范围内资料，任何一端都能离线编辑。无需网络账号、互联网或固定地址；不提供外网、NAS/服务器中转、手机互连、媒体搬运、多设备管理或恢复云服务。优先做好两台设备之间的恢复与冲突处理，再扩平台。

## 2. 一次配对与日常状态

1. **Mac：**在“设备同步”选“配对 iPhone”。首次在前台解释“允许 LexiCue 在局域网内连接你的 iPhone”，执行服务注册以触发必要系统授权；显示临时二维码和到期状态。过期后唯一主操作为“生成新二维码”。
2. **iPhone：**同一入口选“扫描 Mac 二维码”。仅此时说明并请求相机权限，识别后停止相机；随后浏览指定 Bonjour 服务，由系统按需询问局域网权限。不给相册、麦克风或其他无关权限。码不是永久通行证。
3. **两端核对：**显示“此 Mac ↔ 此 iPhone”的实际设备显示名及同一个六位核对码。用一句话告知：“首次将合并两台设备的资料；之后的修改和删除也会同步。”主操作“验证码一致，配对”，次操作“取消”；码不同就取消重来。两端各确认一次，仅扫码或仅一端同意不会授予资料权限。
4. **首次合并：**信任建立后自动检查版本、空间并分别生成可恢复的本地副本。两端就绪后才开始合并；按材料显示进度，离开设置可继续阅读。失败指出哪端、哪一步，例如“iPhone 空间不足，首次合并尚未开始”；修复后重试，不引导用户整体恢复。
5. **以后：**正常同步只更新设置页；不弹窗，不在阅读页、悬浮栏加入口。连接下的“设备详情”折叠显示最近一次双方确认时间、当前问题及“移除设备”。移除确认：“停止与此设备同步。两端已有资料都会保留。” 不用“删除资料”命名操作。

| 设置主状态 | 判定与退出条件 | 用户下一步 |
|---|---|---|
| 等待设备上线 | 已配对，无可用会话；或 Bonjour 超时、对端休眠/退出、网络隔离原因未明。可附“本机有待发送的更改”和上次确认时间 | 打开两端应用；持续失败才提示换到允许设备互访的网络，自动重试 |
| 同步中 | 双向验证完成，正在备份、合并、补传或等待写入确认 | 无；首次显示阶段，字节到齐不能显示完成 |
| 已同步 | 已就本轮双方声明的水位互相得到持久化回执，当前无新增待发、待应用或待处理冲突 | 无；断开回“等待设备上线”，保留上次确认时间 |
| 需要允许局域网访问 | 本端取得 policy denied / localNetworkDenied 等明确证据 | 引导到本端系统隐私设置，回来后重试；找不到对端不能推断它拒绝了权限 |
| 需要更新另一台设备 | 该端不支持必要协议/字段；若本端过旧，明确写“需要更新此设备” | 标明设备名并提示更新；不应用、不确认不兼容的更改 |
| 有更改待处理 | 有需人工选择的并发文本/恢复候选，或无法自动继续的写入错误 | 按原因只给“查看版本”或“重试”，具体写明空间、校验或存储问题 |

呈现优先级：阻止安全操作的身份/协议/权限错误 → 需要人处理的问题 → 正在交换 → 离线等待 → 已确认。拒绝相机、码过期、验证码不符是配对步骤的就地错误，不伪装成同步错误。正常页不必有主按钮；需要介入时只给一个主操作。可在已配对的 Mac 详情开启“关闭窗口后继续接收”（默认关）：开时隐藏窗口、保留应用进程与已认证监听，可从 Dock 重开；关时关最后一窗停止服务；⌘Q、系统退出或睡眠均不可接收。不建登录项或无人值守守护进程。

## 4. 三层架构与 Apple 边界

| 层 | 负责 | 接口与限制 |
|---|---|---|
| 本地资料库（Rust/SQLite） | 材料、分句版本、收藏、标签、位置的唯一持久化入口；写业务、字段版本和本地事件同事务。备份、恢复、迁移、摘要对账 | 不在另一台设备挂载、复制或共享活动 SQLite/WAL 文件。读快照用独立连接；网络等待、加密、哈希和大 JSON 解码不持业务写锁。 |
| 共用 Rust 同步引擎 | 协议协商、因果合并、批次/背压、检查点、已应用集合、按 peer 的确认、冲突与状态。连接内两端跑同一逻辑 | 消费已认证的有序字节通道和生命周期信号；无需知道谁是 Mac。React 仅发起用户意图、订阅状态及有针对性的缓存失效；不承担关窗后的调度。 |
| Apple 原生发现与可信传输 | Mac 用 NWListener 注册固定类型 `_lexicue-sync._tcp`；iPhone 用 NWBrowser 查找服务，NWConnection 连接；Network.framework/Security 做 TLS、Keychain，AVFoundation 仅用于扫码 | 原生桥将 verified peer、帧、流控/取消、连接和权限原因交给 Rust。Bonjour 只是发现，广播随机实例别名与必要协议提示，无设备实名、内容、密钥或配对密令。只在配对窗口或已有信任时注册/浏览。 |

**网络与权限。** Bonjour 注册、浏览和解析需本地网络访问；iOS 14 起、macOS 15 起有相应隐私控制。打包时核对两端最终 Info.plist 的 NSLocalNetworkUsageDescription、NSBonjourServices；iPhone 加 NSCameraUsageDescription。只用声明的固定服务类型，无需为普通 Bonjour 申请任意组播能力。不得自行发 UDP 广播或用 WKWebView 扫网段。沙盒 Mac 构建核对来向网络 entitlement；发布签名、防火墙与隐私权限分别验证。模拟器不证明局域网权限通过。[Apple TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy) · [网络 API 选择](https://developer.apple.com/documentation/technotes/tn3151-choosing-the-right-networking-api) · [相机授权](https://developer.apple.com/documentation/avfoundation/requesting-authorization-to-capture-and-save-media) · [Mac 沙盒入站连接](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.network.server)

**可达性。** Mac 接有线、手机接 Wi-Fi 亦可，只要局域网能发现服务并直连。相同 SSID 不代表互通：访客隔离、组播过滤、防火墙均可能阻断。仅绑定/接受本地直连 Wi-Fi 或以太网的本链路服务，不接受互联网地址、蜂窝、VPN 隧道、重定向或端口转发作为发现途径；验证接口、IPv4/IPv6 含作用域及对端路由，地址本身不是身份。NWPathMonitor 变化只唤起重新发现，不能证明 peer 已连通。[Apple NWPathMonitor](https://developer.apple.com/documentation/network/nwpathmonitor)

**调度。** 启动、回前台、发现已配对端、网络恢复/切换、写事务提交、Mac 唤醒均通知同一个单航班引擎。Mac 从 NSWorkspace 的通知中心接 didWake，重建失效 listener/会话；iPhone 才主动拨号。Mac 本地有新数据且已有通道时主动推送；无通道时只记账等待。连续编辑目标合并 500 ms、最迟 2 s 发一批（合并传输，不丢事件）；失败指数退避加抖动，上限 60 s，前台/路径变化立即再试一次。无信任、权限明确拒绝或身份不符时不作高频尝试。[Mac 唤醒](https://developer.apple.com/documentation/appkit/nsworkspace/didwakenotification) · [最后窗口关闭与退出](https://developer.apple.com/documentation/appkit/nsapplicationdelegate/applicationshouldterminateafterlastwindowclosed(_:))

**iOS 后台。** 首版不依赖 BGTask、推送、音频保活或“加入 Wi-Fi 唤醒应用”。进入后台停止开新批次，用系统允许的短暂延时尽力提交当前小批次，及时 end；到期取消网络并安全收尾，未提交的不确认。锁屏、挂起、强退后不保证时效，两端需在某段时间同时可用。双方最近确认时间可见，避免用户误以为手机关着也已更新。[Apple 后台策略](https://developer.apple.com/documentation/backgroundtasks/choosing-background-strategies-for-your-app) · [有限后台执行时间](https://developer.apple.com/documentation/uikit/extending-your-app-s-background-execution-time)

## 5. 配对、身份与撤销

- **首次信任。** 每个安装在系统安全存储中生成独立的 TLS 身份。二维码只含格式版、随机服务会话 ID、Mac 公钥指纹、至少 128 位随机一次性票据和到期信息，不含地址、学习内容或私钥。建议有效 2 分钟，Mac 用单调时钟裁决；取消、重开、休眠、重启都使旧码失效。手机必须先验证实际 TLS 服务端公钥与码中的固定值匹配，再在该加密连接内出示票据。不要用 DNS/TXT 公布的指纹作信任根。
- **核对不是密码。** 配对通道仅允许有限的配对消息。要求手机在握手中证明持有候选客户端证书私钥；Mac 检查票据后原子占用，只绑定该客户端公钥和本次连接，拒绝第二个客户端。Mac 用系统随机源生成六位数，限本次已固定服务端且验证客户端持钥的通道，两屏显示，任一拒绝或断线需新码。验证码不能单独登录。配对帧限长、限频、限制并发；盲猜或拍到二维码都不能绕过 Mac 本机确认。
- **提交信任。** 两端都确认相同的会话、身份对和码后交换完成凭据，把对方公钥 pin、配对 ID 和状态持久化；半完成配对仅允许完成/取消，不传资料。崩溃恢复时若不能证明双方完成，则清掉待定状态并重配。正式数据连接单独握手，使用 TLS 1.3 双向认证、逐次核对固定公钥和当前有效配对 ID；禁用 0-RTT 数据写入。设备名、IP、服务名和同网都不授信。使用系统 TLS/标准库做证书和持钥校验；不自拟加密、密钥交换或用六位码派生数据密钥。此配对流程属于待安全评审的产品协议。[Apple 本地 TLS 身份](https://developer.apple.com/documentation/network/creating-an-identity-for-local-network-tls) · [TLS 1.3](https://www.rfc-editor.org/rfc/rfc8446)
- **密钥与日志。** Keychain 独立服务名，禁止 iCloud 同步；iPhone 推荐 WhenUnlockedThisDeviceOnly，锁定时钥匙不可用就等待解锁，不为后台同步放宽保护。Mac 使用本机私有钥匙串身份并验证访问控制。私钥/票据不进 JS 持久存储、业务数据库、备份或日志。诊断仅记录阶段、计数、稳定错误码和耗时，不写正文、笔记、地址、二维码或完整设备标识。[Apple Keychain 可访问性](https://developer.apple.com/documentation/security/ksecattraccessiblewhenunlockedthisdeviceonly)
- **撤销。** 任一端“移除设备”先持久化拒绝，再关连接、取消在途帧、清除该配对凭据和待定请求；事务提交前复查配对代，避免在撤销完成后再应用排队数据。对端在线可收到经认证的解除通知；离线时不能保证通知送达，但被移除端再也不能通过撤销方读取/写入。两端资料、墓碑、尚未处理的编辑继续保留。再次连接必须由两端明确重配；旧票据、旧会话恢复和同名新证书无效。首版限制一个有效 peer，换机不能静默挤掉旧设备。

## 6. 数据模型、事件与确认

以下为新增逻辑表或等价布局，统一用 lan 命名空间，不修改旧云游标的含义。

| 记录 / 主键 | 必要字段与不变量 |
|---|---|
| 本库与设备 `lan_replica` / peer | 本机安装身份、公钥标识、随机库世代 epoch、单调 next_seq；peer 保存公钥、配对代、状态、已认可的对端库世代。设备身份与库副本身份分开，恢复出的 DB 不能证明持有原安装身份。 |
| 业务映射 / 字段版本 | `(kind, stable_id) ↔ local_id`、可验证别名、恢复代、墓碑；句子有稳定 ID、排序和材料 ID，正文/结构有 revision。按 `(kind,id,field)` 记当前候选的事件点、已见因果向量及值或内容引用。旧记录迁移可重跑，不以本地自增 ID 当跨端 ID。 |
| 事件日志 `lan_events` | 唯一 `event_id`；唯一 `(origin_device,origin_epoch,origin_seq)`（事件点）。保存不可变规范编码与 SHA-256；更新/删除/恢复/冲突解决有各自操作。每个源各自连续分配 seq；本地业务写和序号分配、事件及其载荷在同一事务内全成或全败。 |
| 收件与确认 | `lan_applied` 记录事件点、事件 ID 与摘要；`lan_progress(peer,pair_epoch,origin,origin_epoch)` 分列本地已应用连续水位、对端已确认连续水位。空洞、依赖和暂存另表；对端 ACK 不能跨 peer/世代复用。 |
| 合并、分块与恢复 | `lan_conflict` 用实体、字段、排序后的候选版本集合生成一致的逻辑标识；未解决值、删除时恢复候选与解决事件均持久化。`lan_staging` 存批次、内容块、hash、manifest、进度；`lan_checkpoint` 记覆盖向量、日志下界、墓碑/状态摘要、版本及可恢复备份索引。 |

**帧与消息。** 采用长度前缀 + 版本化 DTO；首版推荐成熟 CBOR 库、[RFC 8949 §4.2 确定性编码](https://www.rfc-editor.org/rfc/rfc8949.html#section-4.2)测试向量与 SHA-256（内容校验/寻址，不代替 TLS 认证）。事件示例为示意，不是现有格式：

```text
EVENT { protocol:1, schema:1, event_id:E, origin:(iPhone, epochB, 42),
        entity:(translation, sentenceS), op:patch, generation:0,
        observed:{(Mac,epochA):18,(iPhone,epochB):41}, parents:[V7],
        base_content:bodyR3, fields:{zh:{text:"……", provenance:user}},
        payload_digest:SHA256(canonical_header_and_payload_without_digest) }
```

`HELLO` 仅在认证后交换协议范围、必需特性、实体 schema、库世代、日志下界、持久化向量及本轮目标 head；无共同版本/未知必需语义立即停止业务写入，不跳过后假装确认。此后可交换 `WANT`（向量差/缺块）、`MANIFEST/CHUNK`、`EVENT_BATCH`、`APPLIED_ACK`、`ROUND_DONE`、可重试/不可重试 `ERROR`。源序号必须与授权 origin 对应；首版不接受第三方转发的陌生来源写入，历史世代的状态只能作为已认证、已对账的快照输入。严限帧长、解码深度、块数、解压后尺寸及暂存配额；未知消息不交给 SQL。通道两方向分别授予流量额度，收藏等小更新可穿插大正文块。

**一次普通交换。** ① 各端交换已应用连续水位与本轮 head；② 按对方缺失区间发送不变事件或缺块，先满足父依赖；③ 接收端校验权限、版本、摘要、实体约束、因果依赖，在单一写事务内合并业务、保存冲突/墓碑、写 applied 与推进连续水位；④ 提交成功后发携带配对代、来源世代、水位的 ACK，发端仅接受不超已发送/已验证快照边界的确认并持久化。接收端提交失败/磁盘满/只读/校验错均不前移、不 ACK。事务内区分本地写与远端应用，不重新制造同一编辑的本机事件；用户解决冲突才生成新事件。对关键写入验证 SQLite 的持久化设置（WAL + synchronous=FULL 或等效方案）及错误传播，不能只凭内存成功回调。配置以各写连接读回的设置为准，参照 [SQLite synchronous](https://www.sqlite.org/pragma.html#pragma_synchronous)。

**重传例子。** iPhone 已把 Mac 第 18 条写盘，ACK 在断网时丢了：重连通告已应用 18，或收到相同 18 后校验已应用记录并重发 ACK，不再添一条收藏。缺 17 时即便持有 18 也不能报连续 18；同一序号或事件 ID 对应不同摘要则停止并要求对账，绝不任选其一。两端交换 ROUND_DONE，条件为本地确认覆盖对端 head、对端回执覆盖本地 head；若产生新写入，更新目标继续一轮。已保存的冲突候选可以确认“收到了”，但有未决冲突时 UI 仍为“有更改待处理”。

**首次合并与长材料。**

1. 启用迁移先做可恢复副本；为没有可用因果史的旧行建立一次性基线版本（彼此独立，不伪造先后），保留可信旧墓碑。颜色和位置从 WebView 做有回执的幂等迁入，旧值保留作恢复；按已验证来源匹配本机材料，歧义留本机。启用后任何业务写入立即纳入事件事务。只为已启用的副本维护新增 LAN 历史。
2. 两端分别在一致的 SQLite 视图捕获范围内记录、字段版本、候选、关系、别名、墓碑与同一时点的高水位 H。**推荐把经校验的合并前数据库副本作为该端的固定快照读取源**（在其中读 H），离线序列化允许传输的字段；不发送 DB 文件。新的句子分配 UUID 并持久保存；旧分句一次性映射到 UUID，重复句不能只按句文生成 ID。只在已证明的同源同修订下用顺序、句文和时间轴建立旧句别名；改词或改序可延续已知句 ID，拆分/合并创建新 ID 并记录前身。先短暂协调激活写跟踪，备份用专用工作线程/连接，评估 WAL 与磁盘峰值。任一端备份、校验或空间预检失败，双方都不开始远端应用。新写入 > H 留在日志。
3. 快照清单按实体/材料修订分段，内容按有界块、总长度和全量摘要校验；临时表/版本表分批落盘。先传父映射，再传句子/译文、收藏及关系。按完整材料修订原子切换可读版本，单条收藏可独立发布；有新本地编辑时按同一因果规则合并，不能用快照覆盖。外键缺失则等待/请求父项，不能露出半份字幕。暂存回执只用于续传，绝不是 APPLIED_ACK。
4. 两边独立完成相应清单后，才确认快照覆盖的 H（不跳过依赖或未处理的行）；继续互传 > H 的增量，直至双方确认。本轮期间仍可导入、收藏、阅读。保存快照 ID、覆盖向量、已提交单元和缺块；任一端重启优先续传同一清单，清单失效则重新捕获、按版本幂等合并，不回滚已完成部分。
5. 长材料正文按不可变块寻址，句文、句序/时间轴、译文按稳定句 ID 分开；同一结构修订有完整 manifest。修订边界内必须一致（正文与句序不能各选一个版本）。小编辑仅发变动字段/缺块和新清单，限制同时解码的块数；禁止旧协议那样删光分句重插。

## 7. 合并规则：看编辑基于哪个版本

只用设备时间显示“何时编辑”。因果向量覆盖对方事件点即已观察；已观察版本的后续编辑可以替代它；两边互不覆盖就是并发。不同字段分别比较。协议中的 observed 用于传输依赖；替代某一字段的值还必须指明编辑器实际基于的字段父版本。比如打开笔记后收到远端编辑，保存旧表单不能因为数据库已见新版就吞掉它。只有实际引用并解决了两个候选的新版本才能关闭该冲突。并发无损字段可以自动归并；需要一个当前显示值时，用稳定的事件点全序固定选择，两端展示一致，不以接收先后或“本地优先”决胜。

| 场景 | 默认结果与用户可恢复内容 |
|---|---|
| 两边独立新增、重复事件 | 不同 ID 都保留；相同 ID、相同事件摘要幂等。相同旧 ID 但不可变来源矛盾时隔离，两份数据保留，不能把它当重传。 |
| 两份相似材料 | 默认并存。只有可验证的相同来源身份、完整规范化正文/句序/时间轴摘要相同且来源、锚点一一对应才自动建双向认可的别名，规范 ID 确定性选取，同步重映射标签/位置等引用。纯文本无来源证据的独立导入宁可并存；标题、短 hash、相同句子或向量相似度都不够。别名不吞掉任一侧独立的字段修改。 |
| 正文、句序与标题 | 标题与分句译文等不同字段自动合并；兼容基线下不同句的独立改动合并并重建一致正文。对同一范围并发改文、重分句/时间轴冲突时保留两份完整修订供选择。原文修订不匹配的译文保存在原句版本下，不能贴到另一句。 |
| 译文/个人笔记/释义 | 缺失值不是擦除指令；自动补空只能填空。人工与自动竞争时保留人工为当前；来源不明的旧非空译文按受保护处理。显式清除是一个用户版本，自动结果不能将它复活。同字段两个不同人工版本保留全文，设置显示设备与版本，可选其一或编辑合并；解决事件引用全部已见候选，未见的并发候选仍在。两份不同自动译文可确定性选一并留候选，无需打断阅读。 |
| 收藏及上下文 | 以稳定来源、材料、句 ID、选区和表达核对身份；同词不同材料/句子/选区分开。材料删除后收藏快照仍可阅读，原文跳转标为不可用。旧 source_key 在独立导入/短哈希碰撞时可能同值：增加稳定来源域、迁移去重索引与身份校验，保留旧 record_id 别名；对不兼容上下文分配不同新 ID，不强行写旧唯一键。 |
| 标签/关系 | 颜色随标签 ID，改名不丢颜色；不同属性分别合并。遵守当前 name_key 唯一约束：同名独立创建且语义一致时建别名并集关系；改名碰撞或语义不明则两份候选暂存，先用确定性可区分显示名，待用户选择，不能因 SQL 唯一键丢标签。成员关系采用 observed-remove：移除只撤销看见的添加，独立并发重加保留；父材料/标签的墓碑盖过旧边。不整组替换标签。 |
| 删除、编辑、恢复 | 同代内删除优先于迟到/并发编辑，主列表隐藏；旧行或快照不能复活。并发编辑原文进“可恢复的编辑”（包括材料下并发的句文/译文）；仍被收藏引用的原句照留。显式恢复需引用当前墓碑并开新 generation；旧代重放无效。选择“恢复并采用此版本”也同步，不能把取消配对或手动恢复备份解释为批量删除/复活。 |
| 阅读位置 | 锚点 = 材料 ID、正文修订、稳定句 ID、导航意图、会话及所见位置版本；可选句内字符锚点，绝不发送像素。只有用户滚动停稳、跳句或主动回读才产生意图，页面打开/布局变化不回写旧值。一段会话从进入时所见的锚点版本派生，后台收到的版本不伪装成本人已读。顺序更新按因果；并发主动跳转/回读优先于普通进度，相同优先级按事件点确定性选一个并保留另一个候选；不取最远句。已在读的页面保持原位，下次打开采用合并结果。句子消失可按同修订映射/唯一邻句锚点回落，歧义则从章节/开头进入，不误跳或传出伪事件。 |

例：Mac 已读到第 40 句，iPhone 看见该位置后主动回到第 12 句。第 12 句是新的有效意图，Mac 下次打开应回到 12；若 Mac 正在阅读第 40 句，本次画面不动。仅打开离线旧页面并恢复本机滚动位置，不能产生一条“覆盖所有新位置”的编辑。

## 8. 断线、恢复、清理与重新加入

| 条件 | 自动行为 / 恢复入口 |
|---|---|
| 断网、换网、Mac 休眠、iPhone 挂起或进程终止 | 放弃连接，不放弃已提交的业务或待发日志。回前台/唤醒后重新发现、验证身份并交换水位；暂存按清单续传。只提交了一端的首次合并同样可重放，不要求另一端“恢复出厂”。 |
| 写入失败或空间不足 | 回滚当前发布事务，已发布的完整材料可读；标明失败端、未确认阶段和所需空间。清理的只能是可再取的临时块。空间恢复后从最后已提交单元续传，保留本机未传的收藏与修改。 |
| 双方摘要不符、日志有缺口或低于保留线 | 停止报告“已同步”，以同一覆盖向量比较按实体桶的规范摘要（含字段版本、墓碑、别名和冲突，排除本地 ID）。只请求不同桶的版本清单；补父依赖、缺块和事件。还不能证明一致则双方备份，重新快照对账；不以任一库覆盖对方。异内容复用同一事件点视为副本分叉，禁用该旧世代继续发布。 |
| 手动 JSON 恢复 / 回滚合并前副本 | 在备份区域提供“恢复合并前副本”，注明设备、时间及“替换本机、暂停同步；不会撤回另一端的资料”。与正常首次合并分开。先暂停/排空所有 LAN 写入，备份当前数据；在私有临时库校验版本、完整性、外键与可读性，再经可中断恢复日志原子切换关闭后的库及连接，处理 WAL/SHM，不在活动连接上换文件。失败可回到原库；成功后隔离旧的 peer、回执及身份元数据，必须以新库世代重新对账。恢复同时期的本机变更可从恢复前副本取回。 |
| 重装、数据库被拷贝或回退 | 本机身份使用不随 DB 复制的 Keychain 安装凭据和非备份的安装标记；重装不假定钥匙串一定清空。缺安装标记/库世代不符/对端已确认值大于本端日志 head 时禁止续用旧来源序号。对非受控回滚，在库外持久维护下一批序号的防回退边界：分配前先安全预留，每次进程恢复若无法证明日志连续则关闭旧 epoch 并换新，不在连续向量里人为跳号。正常干净重启可核对封存水位复用；不能证明则走对账，不盲目信任旧 DB。重装换安装身份、重新配对；同安装手动恢复也须由两端明确确认重新加入。 |
| 重配与陈旧副本 | 发行新的配对代，保留业务稳定 ID 和已知墓碑。先交换删除摘要和存活版本，再合并；无可靠血缘的旧备份行（尤其是没有文件稳定 ID 的导出）先隔离为“从旧副本找回的资料”，可查看、导出并显式作为新记录加入。不把“不在快照里”当删除，也不把不能区分于旧删除的条目当新创建。真正新设备上可证实独立创建的资料照常合并。 |

**安全清理。** 首版不按“超过 N 天”自动删除最后的删除证据。按所有仍受信 peer 对各来源的持久化 ACK 求下界；仅在有经过验证、覆盖该下界的检查点，且不被重传、首次快照、冲突或恢复引用时，才压缩已确认历史/去重明细。保留因果覆盖向量、世代、摘要及紧凑的永久身份墓碑（至少 kind、ID、删除代和点）；低于压缩线的重复帧不再次应用，无法验明的旧批次要求对账。离线 peer 不能因超时被视为确认。磁盘压力下可把已封存版本打包为新的可校验快照，落后端强制走快照；不能为了腾空间删掉唯一待发修改或未解决内容。撤销设备后它不再阻塞日志压缩，但删项摘要与身份隔离仍有效。内容块仅在无存活修订、恢复候选、暂存/快照等引用时回收。

**副本留存。** 双端分别保留本次合并前的、能恢复的最后一份安全副本及索引；失败不自动删除。新副本验证前不轮换旧副本，合并未结束或冲突待解决时固定相关副本。备份在私有应用目录（iOS 不放可共享 Documents）；核对系统备份策略、文件保护和可用空间。公开导出扩展版本以保留稳定 ID、颜色、位置和必要版本/墓碑，并保持读取旧备份；不导出信任、私钥、LAN 投递进度。验证在还原后的副本中既能读到旧笔记，也不能复用旧信任。撤销历史应由独立于可回滚 DB 的安全记录裁决。

**性能门槛均为设计目标，非实测。** 建议固定一个 50 MiB 范围内逻辑数据集（含一份 10,000 句材料、合计 10,000 条收藏、重复句/长句/字幕与中文，原始媒体不计），另用当前真实导入上限附近的匿名单材料测试。记录设备型号、OS/应用构建、有效局域网吞吐、RTT、冷/热启动、可用空间和基线；例行基准要求本地直连吞吐 ≥50 Mbit/s、RTT ≤20 ms。每项至少 30 次交互取 p95，首次大库端到端至少 5 次分别报告，不用单个均值替代失败样本。

| 指标 | 目标与测量方法 |
|---|---|
| 在线小改动 | 已建立连接时，从业务提交到对端持久化 ACK 的 p95 ≤3 s（含合并窗口）；冷发现/前台恢复至首次已认证会话 p95 ≤5 s，系统权限等待单列。双端 trace 用事件 ID 对齐；往返时间在同一端用单调钟计。 |
| 批量吞吐与恢复 | 上述 50 MiB 两机从备份开始到最后双向 ACK 的目标 ≤120 s；备份、摘要、传输、提交各自计时。初始每批 ≤128 事件或 256 KiB、单块 ≤256 KiB，按锁等待动态缩小；超大单值分块。断线续传仅请求缺失块/事件，已确认完整材料不重传。 |
| 阅读与写入 | 同步期间滚动 p95 帧间隔 ≤32 ms，收藏点击至本地提交 p95 ≤150 ms，短写事务持锁 p95 ≤20 ms。用 Instruments/原生 signpost、WebView 帧时序与 SQLite 锁等待对照无同步基线；备份与首次迁移也单列，不能从指标里剔除卡顿。 |
| 增量与资源 | 10,000 句中只改一条短译文时，已预热会话内应用层增量目标 <32 KiB，与材料长度无关；测试字节包含清单/ACK。接收最多 4 个在途块；超额背压，不将整份长材料或全库载入内存。跟踪增量峰值 RSS（目标 ≤64 MiB）、WAL/暂存/备份磁盘峰值和前台耗电；空间预算随实际库预检，禁止无上限堆积。 |

## 11. 待验证事项与决策门槛

| 风险 / 尚未验证 | 推荐决定、代价与判据 |
|---|---|
| 原生身份、系统版本和网络组合 | 一组 Apple 原生网络适配器加一个 Rust 引擎，避免双份合并实现；代价是签名、iOS 15 真机兼容与桥层测试。用正式签名 Mac、最低可得及当前 iOS，验证 IPv6、有线+Wi-Fi、拒绝后恢复、钥匙串锁定、换证、公钥固定和客户端持钥证明。不可用时选兼容的系统 TLS 接口或明确提高支持下限，不回退到信任所有证书。 |
| 旧记录证据不足 | 历史上没有事件或稳定身份时，软件无法判断“当年已删除”还是“从未存在”。推荐保守隔离歧义、保留上下文，接受少量重复；不按相似标题猜合并。用来自旧版的匿名备份确认迁移映射与可恢复数量，再定是否需要专门的历史迁移提示。 |
| 单连接数据库争用、超大正文 | 现有业务读取仍会竞争 DbState 锁；将耗时工作搬离 UI 线程本身不等于不卡顿。优先用固定磁盘快照、独立读连接、短写批和版本切换；代价是额外磁盘与迁移复杂度。若备份测速不达标，换成 [SQLite 在线分步备份](https://sqlite.org/backup.html)并沿用完整性校验与双端就绪门槛，不降低数据保证。 |
| 锁屏、App Nap 和关窗 | 首版只承诺前台 iPhone 与仍在运行的 Mac；关窗选项须在签名包验证隐藏窗口、Dock 重开、显式退出、休眠，以及锁屏后密钥/文件保护的实际行为。无法稳定接收时关闭该选项并明确“请保持 Mac 应用窗口打开”。 |
| 保留成本与冲突操作 | 首版保留紧凑墓碑和未解决的文本版本；空间换取长期离线安全。经真实库测量再定可轮换的额外安全副本数、检查点间隔及默认批量上限；不能按日期删除最后保障。冲突页只需比较、采用或合并，不建通用版本历史浏览器。 |

发布评审先看三个证据：两份非空库在断网/重启后能收敛；任何“已同步”都能追溯到对端持久化回执；用户能从两端各自的安全副本找回合并前的资料。三者任一缺失，首版继续保持关闭。

## 12. 首批实现与复验入口

首批实现覆盖阶段 A 的 Apple 传输探针和阶段 B 的本地准备。Mac 产生限时单次二维码，原生探针能解码图像、注册和浏览 Bonjour 服务，并用预置双方公钥指纹的 TLS 1.3 连接交换测试字节。每次测试独立生成临时证书。Mac 上可运行 `scripts/check-lan-transport.sh`，设置 `CODE_SIGN_IDENTITY` 可验证开发签名构建。脚本同时用 iPhoneOS SDK 编译最低 iOS 15 的共用代码。真机相机、系统权限、首次身份核对、信任保存以及关窗/唤醒仍待接入和验证。

Rust 功能 `lan-sync` 默认关闭。原生调用方可用 `prepare_sentence_ids` 显式启动首个迁移。同一批次号在重试或重启后会取回原安全副本，再为英语分句分配持久标识。回归用例依次执行材料导入、收藏、备份、离线编辑、重开副本和隔离恢复，另覆盖并发重试、损坏副本、历史语言及分句插入回滚。在 `src-tauri` 运行 `cargo test --locked --lib lan_sync::`。阅读收藏的事务与回执实现见第 13 节。产品设置入口将在可信配对与双向合并具备后接入。

## 13. 阅读收藏：事务、回执与双库复验

本批交付一个可独立验证的同步单元：已配对的两份库在建立连接时交换阅读收藏。它仍在默认关闭的 `lan-sync` 功能内。首次启用须先生成已验证的本机安全副本；随后在一个 SQLite 写事务中登记配对及两端库世代、安装触发器，并把现有阅读收藏作为起点加入队列。离线新增、编辑、软删除和撤销沿用现有业务写入，无需等待网络。业务行、不可变版本与待发事件同成同败。

接收端校验协议、路由、连续序号、事件摘要和收藏结构，将业务记录、版本、去重凭据及接收进度一起提交；只有成功 COMMIT 后才能生成该批回执。发送端核验回执的方向、序号和摘要后，在本地持久化确认进度。已提交但未回执的事件会重传，接收端匹配已存凭据后重新回执，无第二条收藏也无回声事件。两端分别发送自己的修改，按本轮握手记录的上界分批追赶。当前每批最多 64 个事件、累计 4 MiB 收藏快照；这是保护上限，不是大库性能实测值。单条超限、未知快照字段、来源文件名包含本地绝对路径或事件分叉都会停止该轮，不跳过未确认事件。

并发的收藏版本均保留，同一代删除优先；明确撤销删除才推进恢复代。整库恢复会在替换事务中停用旧会话，禁止沿用原回执。此批之后的材料支持见第 14 节。发布前仍需实现历史清理、重新配对后的对账、冲突选择、正式 App 配对与前台调度。

| 复验 | 方法与观察结果 |

## 14. 材料增量与断线续传

完成一次阅读材料导入后，标题、原始正文（含原换行）、有序的分句、字幕起止时间和已有中文译文在导入事务中形成一份不可变快照。启用同步前已有的英语 TXT/SRT 阅读材料也在准备事务中纳入日志。文档导入同步其已提取的阅读内容。原始音视频、下载地址和文档提取元数据不在本批范围。

每份初始材料占一个事件序号。会话协议第 2 版允许接收方按已落盘的字节偏移请求下一块。每个原始块为 32 KiB，末块可以更短，逐块校验 SHA-256，并在收齐时验证整份负载的摘要。暂存可以跨进程重启。发布事务一次性写入文件、全部句子及身份映射，同时推进接收进度。只有该事务成功后才返回应用回执；暂存字节数供续传使用。已收齐但发布失败的材料可直接重试发布。双方能力不一致时，停止本轮交换。

后续修改按字段记录。单句改译携带材料标识、稳定句子标识、英文修订、译文和版本信息。超过 16 KiB 的字段事件也使用分块传输。原文相同的句子按稳定标识分别处理。人工改译优先于自动补空，并发候选留存。英语原文已修改时，旧修订的译文仍归属于原修订。来自同一旧资料库的副本可能独立分配过句子标识，只有材料身份、原始正文、分句和时间轴都匹配才关联这些标识。来源独立的材料各自保留。

| 验证 | 已观察结果 |
|---|---|
