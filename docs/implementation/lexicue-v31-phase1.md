# 第一批交付：独立保存、旧数据迁移与管理

2026-10-24，Asia/Shanghai。分支 `codex/lexicue-v31-pure-b`，基于 `22d05a0`。本批覆盖阶段 0 和阶段 1 的本机数据底座及管理入口；完整 B 主流程尚未交付。

## 可以操作什么

运行本分支的 Tauri 开发版后，从 **设置 → 已保存 → 打开已保存** 进入 `/saved`。这是阶段 1 的入口；阶段 2 将按定稿把“材料 / 已保存”放进紧凑 B 功能坞。

- 搜索表达、解释、原句和出处；按需加载更多。
- 打开保存的上下文、修改解释、查看旧个人注释与英语修改、返回原文。
- 来源已删除或变更时，继续读副本并得到明确反馈。
- 省略号移除；撤销恢复同一保存身份、原句、解释、出处和原保存时间。
- 卡片无叉号；专用空白区、Esc、系统返回可收起，焦点恢复。编辑草稿在本页收起/重开时保留；写入失败能重试。
- 迁移说明和冲突版本按需展开，不增加常驻引导条。

新记录的保存命令已实现和验证；正式阅读页仍走旧解释/词状态链，尚未接入新保存按钮。本批不能声称已经完成“真实 SRT 导入 → 查询 → 保存 → 继续”。

## 数据保护与实现

新增 `saved_records`，原句、解释与出处是独立快照，没有到材料或旧词条的级联外键。表达与来源位置由后端唯一约束去重，包括选区首尾空白规范化；同表达的新位置分别保留。事务内一起提交写入和回执，失败整笔回滚；撤销校验 revision，不能覆盖后续修改。重复保存的撤销不会删掉原有记录。新保存不调用旧 learning / review 写入链。

升级先用 `VACUUM INTO` 备份现存 SQLite（包括 WAL 已提交内容），再迁移。失败停止该升级；不清空旧结构。备份 schema 9 包含快照、删除墓碑、撤销回执、迁移报告、冲突双方及旧 annotation 回执；恢复兼容 1–8 和逐行缺失的新字段。旧 category 字段只作数据兼容。

同步以独立 `saved_records` 加密实体发送，材料不存在也能到达。删除在同一生命周期中优先于并发编辑；明确撤销/重新保存进入下一生命周期。个人解释冲突保留双方。CAS 重试会重建旧信封并观察远端时钟，避免重发旧时钟造成两端分歧。

旧库副本发现的两个额外问题已修复：同位置重复出现记录保留全部旧内容；一次性英语元数据回填不再每次启动都重写既有历史分类。恢复时避免为每个字幕/词位置重复扫描同步队列，同时仍给材料排入完整快照。

旧库审计只对只读连接导出的临时副本操作。123 个单词和 44 个短语有主动积累证据；976 条现存上下文及 27 个原本缺来源的条目，去掉 5 个重复位置身份后，得到 **998 条保存记录**，重复内容仍完整保留。非英语、纯自动提取和仅 known / ignored 内容留历史。

迁移前后材料、词条、上下文、计划、作答逐表内容指纹一致；恢复后的全部备份数据逐表指纹一致（保存表的设备内整数行号可变，稳定 `record_id` 及全部内容一致）。外键检查为 0。迁移重复执行不增生、不复活已移除记录。

本机该副本最终测量：迁移约 **1.76 秒**，恢复约 **4.46 秒**。早期恢复测试约 126 秒，逐字幕排队修复后明显降低。这些是此设备/此数据集的开发测量，不是查询 p95 或跨平台承诺。

自动化还覆盖十次重复保存、多连接并发、无解释保存、来源删除、写入回滚、移除/撤销、重启、旧备份缺字段、损坏备份回滚、个人解释保护、先到墓碑、延迟编辑、明确恢复、加密信封与并发冲突。

UI 检查使用隔离内存 Tauri fixture，不能替代真实 Rust/SQLite。覆盖 ocean / midnight，360、390、430、768、1024、1280、1440 宽；正常、悬停、选中、禁用、焦点对比度，较大字号、减弱动画、键盘返回、失败草稿和准确撤销。默认桌面及午夜窄屏截图已人工查看。

本机日志位于 `/tmp/lexicue-v31-{build,lint,tests,cargo,copy-audit,ui-all}.log`。截图与界面报告位于 `/tmp/lexicue-ui-saved/`；无真实词句数据写入仓库。
