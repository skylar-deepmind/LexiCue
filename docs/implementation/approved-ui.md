# Approved desktop and mobile reading surfaces

Source: [LexiCue Figma](https://www.figma.com/design/FsjOfhLGQ7Rs5Ig9pfCVpK), desktop `383:14757` / code layer `462:14758`, mobile `480:3` / code layer `539:3`. The delivered handoff source and its design measurements are the implementation reference. The React application renders real material and saved-record state; it does not embed the prototype, an iframe, a screenshot, or sample article content.

## Product mapping

- `/files`: actual reading desk members (opening a wall material places it back on the desk), stable content-identity covers, remembered source sentence, keyboard/touch carousel, clipboard import, file import, tag editing, and a miniature of the real first saved folio in the pocket. Clipboard and file imports have separate controls. File import opens the system picker directly; cancel leaves no source chooser. The old two-source chooser is removed; all three header actions have illustrative hover feedback.
- Material library: real tags and counts, desktop horizontal projection wall, phone two-column layout derived from actual character counts; scroll/focus are retained per tag, including WKWebView’s delayed focus scroll before reverse geometry is measured. The tag rail and poster wall have no manager/menu escape route. Legacy `view=manage` URLs replace themselves with the approved library route. Hold a material card and drop it onto the open trash basket to confirm deletion through the existing backed-up native deletion job; dropping elsewhere cancels.
- Reading: the existing native reading, translation, dictionary, saved-record, recall and audio services. Entrance and reverse return use the real source sentence and element geometry (580 ms desk, 1320 ms wall). An opaque snapshot retains the shell’s inherited layout and is captured synchronously before navigation, and the live reader stays hidden until the handoff is installed. On the desk, the excerpt lands before the title and cover complete; surrounding prose fades in after the excerpt, and contours travel with the cover. On the wall, the whole selected poster contour stays fixed and clipped to the wall viewport. The prototype’s radial light reveals the reader while one short phrase moves as a unit. Entrance and reverse share the same 1320 ms sampled exposure curve; no title or cover flies across the wall. Reading uses one floating translation/listening capsule on desktop and phone; listening splits into play/pause, rate and return-to-reading controls. Format badges, paragraph labels, sentence numbers and the reading font menu are omitted. Re-encounter hints remain configurable in dictionary preferences; a failed index or matching Worker exposes an inline retry only while reading is affected. Cover contours come from actual loaded artwork pixels. Cross-origin thumbnails fall back to paper exposure when canvas access is denied. Reduced motion skips the flying desk elements and uses a 140 ms wall fade.
- Dictionary: one supplemental lookup action stays inside the current card. Local meanings remain visible during pending, no-new, error and additional-meaning results. Provider settings remain available in dictionary settings.
- `/saved`: the pocket miniature pops out and expands into the matching folio (180 ms extraction, 480 ms handoff, 430 ms return); the full folio stays spatially fixed, and changing contexts alone uses the 185 ms slide. Other saved-page navigation keeps its dissolve. Native date histogram and pre-grouping date filters, searchable entries, real source snapshots, multi-context paging/swipe, inline personal explanation, remove/undo, exact sentence return and view restoration. The old saved manager and its menu are removed; legacy `view=manage` URLs normalize to this folio. Hold a sentence and drop it onto the open trash basket to remove only that record; cancellation makes no write, and the existing revision-aware Undo restores it. The same gesture applies to the lookup card’s saved-context history. Holding then tapping the basket and Delete/Enter keyboard confirmation provide alternatives, with Escape to cancel.
- Settings: preferences/data/tools/updates remain available in detail pages, including software update. Category labels are not repeated in the content paper. Phone category tabs have equal width and centered labels; version facts use the paper background without an extra boxed row. Four interface languages use one inline segmented control; the old first-use/replay guide is removed. Optional YouTube profiles and diagnostics are disclosed under advanced options, with a concise local-session privacy notice. Combined dictionary books and online preference, five persisted speech voices with real preview and connection controls, backup, sync and update services.

Artwork in `public/design` comes from the supplied handoff: ten prints, wordmarks, projector photo, five voice portraits, map states and the book decoration. The map/book vectors were extracted from the handoff's own embedded source. Content identity allocates an existing print deterministically, so rename/backup/restore does not shuffle covers; YouTube uses its source thumbnail with a bundled fallback. No new custom-cover upload/database field is introduced.

The runtime no longer mounts the hidden old sidebar, workspace header or mobile navigation. The old material/saved manager components are deleted. `/example` redirects to the desk instead of reopening onboarding. Read-only historical records remain available for backup and export.

## Data and compatibility

There is no schema migration. Import `tag_ids` is optional and empty input preserves the existing request hash. Valid tags and material commit in one transaction; duplicate imports never silently retag a file. Invalid tags roll back the material and operation receipt. Saved date filters apply before grouping and searching, while existing unfiltered callers retain their entry points. Native reading positions and saved-record revisions remain authoritative. Backups and device-sync schemas are unchanged.

The exact local headword now leads source aliases in dictionary overviews (`air` before the historical `air → be` relation); the related entries remain available and saved snapshots are unchanged.

## Verification entry points

- `node scripts/ui-approved-cleanup.mjs`: both themes on desktop and touch-sized phone, first-frame snapshot geometry, fixed wall contours and reverse masks, direct file-picker cancellation, retired manager routes, flat version facts and centered tabs, drag cancellation, real saved-record delete/Undo and the material-deletion failure boundary. Native gestures and actual system pickers require the separate per-device evidence.

- `node scripts/ui-approved-feedback.mjs`: both themes at 1360/390/320, painted footer alignment, hover artwork, real miniature/source correspondence, handoff choreography, independent collapsed/expanded listening hit targets, inline languages, update navigation and concise YouTube settings.
- `npm run test:ui`: current approved surfaces, their persistence/failure paths, detailed import boundary regression, and the existing 10,000-record re-encounter regression.
- `node scripts/ui-mobile-reading.mjs`: large type, portrait/landscape, original geometry and scroll across half/full/closed drawers, supplemental no-new and reduced motion.
- `node scripts/ui-mobile-startup.mjs`: cold startup, inert/focus release, repeated navigation, theme persistence and reduced motion.
- `npm run test:ui:historical`: retained pre-redesign scripts for reference; selectors and shelf/dock geometry in those scripts describe the retired presentation and are not a current acceptance claim.
- Rust tests include tagged import atomicity, date boundaries/search, the exact-headword regression, existing backup/restore, saved-record conflicts/idempotence and device protocol tests.

Browser tests use real Rust command cores and disposable SQLite. File picker, clipboard, external provider and selected failure boundaries are controlled as stated in each script; this is not native UI or physical-device evidence. QA app configs in `scripts/qa` use isolated identities, do not open everyday learning data, and disable updater/shared sync credentials. Native per-device receipts and screenshots are retained outside the worktree. A QA installation is not the post-merge everyday installation.
